1. How the wick is actually drawn

src/client/Chart.jsx:45–83 creates a Lightweight Charts chart and a CandlestickSeries. There is no application SVG line, CSS pseudo-element, custom stroke(), or separate DOM wick.

Position and length

  • X: step mode passes index + 1; other modes pass the time value (Chart.jsx:98). The time scale supplies the bar center. The renderer uses round(x × horizontalPixelRatio) for both body and wick; the wick left edge subtracts half the integer width.
  • Y: the normal price scale maps open/high/low/close using the visible scale range and drawable pane height, with high values near the top. It does not use a hardcoded “pixels per line” factor.
  • Value lengths: upper wick = high − max(open, close); lower wick = min(open, close) − low. Pixel lengths are the corresponding Y-coordinate differences, rounded to device pixels. A small nonzero wick can round to zero.
  • Relative baseline: Chart.jsx:95–107 subtracts the same baseline from all OHLC values. That preserves these differences; it is not a wick magnification feature.

Exact raster implementation, node_modules/lightweight-charts/dist/lightweight-charts.development.mjs:14765–14795:

top    = round(min(openY, closeY) * verticalPixelRatio)
bottom = round(max(openY, closeY) * verticalPixelRatio)
high   = round(highY * verticalPixelRatio)
low    = round(lowY * verticalPixelRatio)

ctx.fillRect(left, high,       width, top - high)
ctx.fillRect(left, bottom + 1, width, low - bottom)

The bottom + 1 start avoids repainting the body's final raster row. Width is selected in physical pixels from device-pixel ratio and bar spacing/body-width logic, ordinarily about one CSS pixel; it is not a configurable application line width. Body-width parity is adjusted to align the body with the wick/crosshair. At very dense spacing the renderer also constrains the wick's left edge against the preceding wick (14742–14751, 14771–14792), so subpixel-density artifacts should be tested rather than called a universal centering guarantee.

Style and render order

Chart.jsx:4–7, 27–30, 78, 107: upward agent candles and wicks are #f05a62; downward agent candles #28d981; unattributed candles #7b8494; the current anchor #e0b34a. Per-bar wickColor is supplied explicitly. Wicks default to visible in the library; borderVisible:false disables the body border, not the wick. Wicks are filled first, then the body (14754–14762).

Why many candles correctly have no protruding wick

// src/core/metrics.js:114 — each newly recorded edit
high = Math.max(open, close)
low  = Math.min(open, close)

Both wick lengths are therefore zero in ordinary step records. Calendar and intraday aggregation preserve intermediate extrema (metrics.js:217–254, 291–306), so aggregated candles can have genuine wicks. The current anchor has open = high = low = close (202–211); the library still renders a minimum-height body. At narrow zoom, a thin body can also look like a wick. Do not manufacture high/low values to add decorative shadows.

3. Targeted repair plan

A. Fix the screenshot's header-width conflict first

  1. Allocate width at the host boundary. In the host source or a supported, scoped extension point, make the utilities wrapper shrinkable (flex:0 1 auto; min-width:0) and reserve an explicit minimum budget for title/actions. Alternatively use a two-column grid with bounded utilities. A child's max-width:100% cannot fix an intrinsically sized, non-shrinking parent.
  2. Compact based on available container width. In ProjectHeader/ProjectTicker, retain the sidebar toggle and core total, then hide brand/recent-change/token fields in priority order. Use a measured header/container budget or container queries, not only viewport breakpoints. Ensure hiding fields cannot collapse the toggle.
  3. Avoid clipping controls or menus. If title truncation is added, confine overflow to text, not all interactive descendants. Do not blindly edit generated host hashes or patch node_modules.

For a plugin-only repair, cap the ticker to an actually measured share of the host title-row space and fall back to a compact total/toggle. Confirm the remaining native title/actions fit before declaring this fixed.

B. Remove persistent marker text in narrow charts

The smallest safe chart patch retains marker symbols and exposes full text in a hover/detail row rather than drawing all strings permanently. Illustrative replacement at Chart.jsx:140:

// Proposal only — not applied. Keep full labels in accessible details.
ref.markers.setMarkers(
  marked.slice(-6).map(marker => ({ ...marker, text: '' }))
);

For wide charts where persistent labels are required: filter to the visible range, measure text with the actual font, prioritize important/recent events, and retain only non-intersecting label rectangles with a small gap. Recompute after zoom, pan, resize, font changes and new data; unsubscribe listeners on cleanup. slice(-6) is a count limit, not a collision algorithm. Merely changing marker z-index or top padding does not solve this.

C. Make chart density and panel size container-aware

  • Use the allocated panel width to decide docked versus drawer mode. Coordinate this with the host layout to avoid a resize feedback loop.
  • Choose the initial visible bar count from actual plot width, with a target readable spacing such as 4–8 CSS px per bar; keep zoom and “show all” available. The current fixed recent-240-bar window (Chart.jsx:142–147) can flatten bodies into thin lines in a narrow plot.
  • If labels remain, compute top/bottom reserves from marker/font needs and the actual price-pane height. Increasing the stage height may help; increasing scale margins within the same short pane can instead compress the candles further.
  • Optionally disable the candle series' default last-value line/label only if it duplicates other UI. These are not the identified header root cause; MA lines already disable their own last-value labels.

Keep the existing OHLC semantics and library wick renderer. Fix layout and annotation density rather than drawing fake shadows or adding broad z-index overrides.
