## 0.3.3 空/满映射：颜色表涨跌，空/满表归属（2026-09-12）

- 先查清了机制并实测确认：轻量图表 5.2.1 的渲染顺序是「影线 → 边框（`borderVisible` 时）→ 实体填充」，实体填充用逐根 `color` 且**四边内缩 `borderWidth`**，因此**不透明 = 实心，`transparent` = 空心（只剩边框）**。隔离实测（`work/hollow-probe.mjs`，黑底红烛逐像素扫描）：实心柱 `-69→+69` 全红，空心柱只有 `-69` 与 `+69` 两个红像素。

## 0.3.4 小改动可见性与包规范（2026-09-12）

**问题**：小改动被大幅改动压成几乎看不到。

**诊断**（先量再改，三个隔离实测）：

- 轻量图表的纵向自适应**严格按可见区间**计算：视口内只有小改动时 20 行 = 96px，插入一根 -10,000 后变 0.58px，把视口缩回小改动区段又恢复 96px。
- 视口外的极值**不会**撑开纵轴：末根跳到 110,000、开/关末值价格线、带不带均线，五种组合实测均为 86.47px／20 行，完全一致。所以「大改动不在视口里却仍被压扁」这个说法不成立——真实原因是**大改动就在默认视口内**。
- 真实账本：`C:/Users/Calx` 默认视口（最近 45 根）纵向跨度 2,318,065 行，其中单笔最大是外部校准 **+2,195,169 行**，而 Agent 单笔最大只有 1,131 行 → 一笔 20 行改动只有 **0.00 px**。这不是渲染缺陷，是口径问题：纵轴画的是「总量」，不是「这次改了多少」。

**修复**：

- 新增第三档纵轴 **每笔变化**：纵轴改为每根柱自己的净变化（0 居中），改动量本身决定高度，不再受总量漂移影响。映射抽成纯函数 `scaledOhlc()`。
- 新增 **仅 Agent** 筛选：只画 Agent 归属柱，外部校准不再参与纵轴计算。这是筛选不是缩放，被隐藏的柱不参与取值。
- 实测对比（`work/scale-compare.mjs`，按 250px 价格区、默认视口估算一笔 20 行改动的像素高度）：

  | 口径 | 轴跨度（全部柱） | 轴跨度（仅 Agent） | 20 行改动（全部 / 仅 Agent） |
  |---|---|---|---|
  | 绝对行数 | 2,318,065 | 2,318,065 | 0.00 px / 0.00 px |
  | 相对基线 | 2,318,065 | 2,318,065 | 0.00 px / 0.00 px |
  | **每笔变化** | 2,196,756 | **137** | 0.00 px / **36.50 px** |

  即「每笔变化 + 仅 Agent」把可见性从 0 像素提升到 36.5 像素。

**包规范**：

- `files` 由整目录 `dist` 改为逐个列出运行时产物：开发用的 `dist/preview.js` 与 sourcemap 不再进包，包体积 **865,033 → 106,563 字节**（9 个文件）。
- 新增 `dsh.client.external: ["react"]`——只列客户端包真正 `require` 的模块（esbuild 走经典 JSX 转换，`react/jsx-runtime`／`react-dom`／`@deepseek-ai/cordis` 都不在客户端包里）。
- 新增 `dsh-plugin.json`（`manifestVersion: 0.15`，host/client 双面入口、权限、订阅）。**已全盘检索：本机 DSH 没有任何代码读它**；格式照本机唯一一个第三方插件 `dsh-thermal-receipt` 的同名清单写，不是从权威规范推导出来的。
